Отличная работа с фронтендом! Теперь нужно доработать инфраструктуру и связать это с бэкендом.
Выполни следующие 3 задачи:
1. Скрипт запуска (Production-ready)
Сейчас мы используем npm run dev (Vite dev server). Мне нужен полноценный способ запуска фронтенда, который можно использовать в продакшене или для тестирования сборки.

    Обнови package.json: добавь скрипты build (сборка статики) и preview (локальный сервер для раздачи собранной статики).
    Убедись, что vite.config.js настроен корректно для сборки (правильные пути, base url).
    Напиши короткую инструкцию, как запустить собранный фронтенд локально через npm run preview.

2. Реальный API вместо моков
В файле src/services/api.ts (или api.js) сейчас стоят заглушки (mocks).

    Удали все моки.
    Реализуй реальные HTTP-запросы через fetch к бэкенду.
    Бэкенд будет работать на порту 5000 (Flask).
    Настрой прокси в vite.config.js, чтобы запросы с фронта (/api/*) перенаправлялись на http://localhost:5000/api/*, чтобы не было проблем с CORS при разработке.
    Формат ответов должен строго соответствовать структуре: { status: 'ok' | 'error', data: ..., message: ... }.

3. Балванки эндпоинтов на Python (Flask)
В папке backend/src/ создай (или обнови) backend.py.
Напиши балканые реализации (stub endpoints) для следующих маршрутов, чтобы фронтенд мог с ними общаться без ошибок 404/500. Пока что они могут возвращать хардкодные данные или пустые успешные ответы.
Необходимые эндпоинты:

    POST /api/login — принимает {login, password}, возвращает { status: 'ok', auth_token: 'fake-token-123' }.
    POST /api/register — принимает {login, password, fullName}, возвращает { status: 'ok' }.
    GET /api/boards — возвращает структуру доски с колонками и карточками (моковые данные, чтобы доска не была пустой при первом входе).
        Структура: { boards: [ { id: 1, title: 'Main Board', columns: [ { id: 'todo', title: 'To Do', cards: [...] }, ... ] } ] }
    PATCH /api/boards/<int:board_id>/cards — принимает изменения (перемещение карточки). Пока просто возвращает { status: 'ok' }.
    POST /api/auth/logout — возвращает { status: 'ok' }.

Важно:

    Используй flask_cors для разрешения запросов с фронтенда.
    Убедись, что все ответы приходят в JSON формате.
    Добавь комментарии в код Python, где потом нужно будет подключить реальную базу данных или логику.

После выполнения этих шагов приложение должно пытаться стучаться на localhost:5000, а бэкенд должен отвечать заглушками.
